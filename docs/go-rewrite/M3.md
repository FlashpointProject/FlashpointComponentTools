# M3 — installer (`FlashpointInstaller.exe`): spec

Read `DESIGN.md` §4.8 and §6 (installer) and `M1.md` (conventions and priorities; they all apply). The legacy installer was `FlashpointInstaller/` (C#, removed with the switch to Go; see the git history).

**Priorities, in order:** correct; real errors handled with clear messages and no data loss; simple code with minimal logic. Do not add code for failures that basically never happen. Comments explain *why*.

## What the installer does

A wizard in the same Gio window code as the manager (`internal/gui`, installer mode):

1. **Destination.** Path field (default `<drive of the installer exe>\Flashpoint`), `Browse…`, two checkboxes "Desktop shortcut" and "Start menu shortcut" (both on), a note when the Visual C++ runtime will be installed, buttons `Next` (primary) and `Quit`. Enter in the path field does **not** advance. `Browse…` appends `\Flashpoint` when the chosen folder is not empty and not a Flashpoint folder (CheckDest then says it is installed there). `Next` validates (`CheckDest`); a problem is shown inline under the field. Valid → create the folder, open an engine on it, take the lock, load the component list (15 s budget, like the manager). Any failure there → close the engine, `Cleanup`, stay on this page with the error inline.
2. **Components.** The manager's tree, details pane and search, without the left rail. Default selection: `Required || DefaultOn` (all but `extra*`, as the legacy installer). The "Will be installed" badge is not shown (every row would have it). Category counts show selected/total instead of installed/total. Footer: the plan summary (download, disk space) and buttons `Back` and `Install` (primary, enabled when the plan is non-empty and valid). `Back` → close the engine, `Cleanup`, back to step 1 (the path text is kept). `Install` starts at once (no confirmation modal).
3. **Progress.** The manager's run screen, titled "Installing Flashpoint". Cancel works until the commit, as in the manager. Not enough disk space → the existing alert, back to step 2. Failed or cancelled → the result with buttons `Back` (to step 2, selection kept; downloads resume from the cache) and `Quit`.
4. **After a successful install** (a close requested during the run no longer applies), in order:
   1. write `<dest>\Manager\fpm.cfg` (`..\` + the source used) via `Options.SaveSettings` (cmd/installer writes it with `state.SaveConfig`, so http test sources work too); a failure is only a note (the manager finds `..` anyway);
   2. if `NeedsVCRedist()`: "Installing the Visual C++ runtime…" → `InstallVCRedist`. On error: modal "The Visual C++ runtime could not be installed" with the plain error plus "The Flashpoint launcher needs it. You can install it later from https://aka.ms/vs/17/release/vc_redist.x86.exe.", buttons `Try again` / `Continue without`. Reboot needed → note "Restart Windows before you start Flashpoint.";
   3. `CreateShortcuts(dest, desktop, startMenu)`; a failure is a note.
5. **Finish.** "Flashpoint is installed" / "It is in <dest>.", the notes, checkbox "Start Flashpoint" (on), button `Close`. Closing (the button or the window's X) starts the launcher when the box is checked (failure → logged), then exits 0.

**Abandoned install.** If the window closes before the components were installed (step 1–3, including a close during the run, which first cancels and waits as in the manager), the engine is closed and `Cleanup(dest, create)` removes what was created (also a missing parent folder that was created for it). Never after a successful `Execute`, even if step 4 failed.

**Window.** Title "Flashpoint Installer <version>", header label "Installer" instead of "Manager", 900×600 like the manager.

The engine needs no change: `engine.Open{ManagerDir: <dest>\Manager, RootOverride: <dest>, SourceOverride: <source>}` works on an empty folder (no fpm.cfg = defaults), `Lock` creates `Components\.fpm`, `LoadManifest` writes `components.bak`, `Execute` is transactional (a failed or cancelled install changes nothing; the download cache in `<dest>\Temp\fpm` stays for resuming).

## API contract between the parts

### `internal/install` (new package; Windows parts in `_windows.go`, stubs in `_other.go`)

```go
// DefaultDest is <volume of exe>\Flashpoint on Windows ($HOME/Flashpoint elsewhere).
func DefaultDest(exe string) string

// CheckDest validates an install destination typed or picked by the user and
// returns it absolute and cleaned, plus create: the outermost folder that
// doesn't exist yet and will be created for it (abs itself or a missing
// ancestor), "" when abs exists (and is empty). Errors are user-facing.
func CheckDest(path string) (abs, create string, err error)

// Cleanup removes an abandoned install: create (all of it) when it is not
// "", else everything inside dir. Only for values CheckDest returned.
func Cleanup(dir, create string) error

// NeedsVCRedist reports whether the Visual C++ 2015-2022 x86 runtime is
// missing (always false outside Windows).
func NeedsVCRedist() bool

// InstallVCRedist downloads, verifies and runs the x86 runtime installer.
func InstallVCRedist(ctx context.Context, log *slog.Logger) (rebootNeeded bool, err error)

// CreateShortcuts creates Flashpoint.lnk (target <root>\Launcher\Flashpoint.exe,
// working folder <root>\Launcher) in root, and on the Desktop / in the Start
// menu's Programs folder when asked. Errors are joined; nil outside Windows.
func CreateShortcuts(root string, desktop, startMenu bool) error
```

`CheckDest` rules (first failure wins):
1. Empty → "Choose a folder for Flashpoint."
2. Not absolute (on Windows: needs a drive or UNC volume) → "Enter a full path, such as C:\Flashpoint."
3. 192 characters or more → "This path is too long; Flashpoint may not work in it. Choose a shorter one." (legacy threshold)
4. A drive root → "Choose a folder, not a whole drive, such as D:\Flashpoint."
5. Windows: inside (or equal to) Program Files (`ProgramFiles`, `ProgramFiles(x86)`; amd64 only, so no `ProgramW6432`), the Windows folder (`SystemRoot`), the temp folder (`os.TempDir()`), OneDrive (`OneDrive`, `OneDriveConsumer`, `OneDriveCommercial`); env vars that are unset are skipped; compare case-insensitively on whole path segments. Messages name the place, e.g. "Flashpoint can't be installed in Program Files, because Windows protects it. Choose another folder, such as C:\Flashpoint." / "…in the Windows folder…" / "…in the temporary folder, because Windows may clean it up…" / "…in OneDrive, because syncing breaks it…".
6. Exists but is a file → "<path> is a file. Choose a folder."
7. Exists and `state.IsRoot` → "Flashpoint is already installed in this folder. Use its Flashpoint Manager to add or remove components, or choose another folder."
8. Exists and not empty → "This folder isn't empty. Choose a new or empty folder."
9. Otherwise OK (`create` = the outermost missing folder, "" if it exists). Writability is found out when the folder is created.

`InstallVCRedist`:
- Detection (`NeedsVCRedist`): `HKLM\SOFTWARE\WOW6432Node\Microsoft\VisualStudio\14.0\VC\Runtimes\X86`, DWORD `Installed` = 1 means present (the 2015–2022 runtimes share it). On 32-bit Windows the key is under `SOFTWARE\...` without WOW6432Node, but 32-bit is unsupported, so don't bother.
- Download `https://aka.ms/vs/17/release/vc_redist.x86.exe` (≈14 MB) over HTTPS with `ctx` into a fresh `os.MkdirTemp` folder (removed afterwards). Reasonable timeout.
- Verify its Authenticode signature with `WinVerifyTrust` (`golang.org/x/sys/windows`, `WINTRUST_ACTION_GENERIC_VERIFY_V2`, no UI, no revocation check). HTTPS from Microsoft plus a valid signature is enough; no signer-name check.
- Run `/install /norestart /quiet` and wait. It is a WiX Burn bundle with an asInvoker manifest that elevates itself (UAC prompt), so a plain process start is enough (verified on 14.44.35211).
- Exit codes: 0 and 1638 (a newer version is installed) are success; 3010 is success with `rebootNeeded`; 1602 and 1223 (cancelled) → "the Windows permission prompt was declined…"; 1618 → "another program is installing something right now…"; anything else → an error naming the code. Once it runs, don't kill it on cancel.

`CreateShortcuts`: WScript.Shell through `github.com/go-ole/go-ole` (already in the module graph via gioui.org/x; make it a direct requirement in go.mod by hand, no `go mod tidy`). COM on a locked OS thread with `CoInitializeEx`. Desktop and Programs folders via `windows.KnownFolderPath` (`FOLDERID_Desktop`, `FOLDERID_Programs`). Description "Flashpoint". Errors read "<place>: <reason>" (Flashpoint folder / Desktop / Start menu), joined with "; ".

### `internal/gui` (installer mode)

```go
// Options gains:
	// Install non-nil runs the installer wizard (FlashpointInstaller.exe).
	// Open is then called with the destination folder (it creates it),
	// SaveSettings writes the new install's fpm.cfg, and OpenLauncher starts
	// the launcher of the last opened folder.
	Install *InstallOptions

type InstallOptions struct {
	DefaultDest     string
	CheckDest       func(path string) (abs, create string, err error)
	Cleanup         func(dir, create string) error
	NeedsVCRedist   func() bool
	InstallVCRedist func(ctx context.Context) (rebootNeeded bool, err error)
	CreateShortcuts func(root string, desktop, startMenu bool) error
}
```

The GUI does not import `internal/install`; `cmd/installer` wires it. Tests pass fakes.

### `cmd/installer` and `internal/launch`

- `internal/launch` (new): the launcher lookup and detached start moved out of `cmd/manager` (`FindLauncher(dir)`, `Start(exe, args, dir)`, the per-OS detached `SysProcAttr`, the launcher names). `cmd/manager` uses it; behaviour unchanged.
- `cmd/installer/main.go` → `FlashpointInstaller.exe`: version var (`-X main.version`), log to `%TEMP%\FlashpointInstaller.log` through `logfile.Sink` (the destination may be deleted by Cleanup, so the log can't live there), optional `--source <url>` (testing and the development channel; default `state.DefaultSource`). `Open(dest)`: `os.MkdirAll(dest)` then `engine.Open` as above, remembering the root. `SaveSettings(root, source)` writes `<root>\Managerpm.cfg` with `state.SaveConfig`. `OpenLauncher` starts `<root>\Launcher\Flashpoint.exe` via `launch.StartLauncher`. User agent `FlashpointInstaller/<version> (gui; os/arch)`.
- Resources: `cmd/installer/winres/winres.json` (icon group `#1` from the installer icon, manifest asInvoker, per-monitor-v2 DPI, long-path aware, win10) and its `.syso`. Copy the icons into the Go tree (`cmd/manager/winres/icon.ico`, `cmd/fpm/winres/icon.ico`, `cmd/installer/winres/icon.ico`) and point the winres.json files at them, so deleting the C# folders later doesn't break the build; regenerate the `.syso` files (`go run github.com/tc-hib/go-winres@v0.3.3 make --arch amd64`).
- `scripts/build.sh` also builds `dist/windows-amd64/FlashpointInstaller.exe` (`-H=windowsgui`; not in core-manager.zip).

## Out of scope

Uninstaller / uninstall registry entry (the legacy installer had none), file associations, signing, GitHub release upload, macOS/Linux packaging.


Characters Windows doesn't allow need no rule of their own: `os.Stat` or `MkdirAll` fails with "The filename, directory name, or volume label syntax is incorrect." (checked), and Cleanup removes a parent created before that failure.
