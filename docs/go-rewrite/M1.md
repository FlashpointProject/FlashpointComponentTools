# M1 — core + `fpm` parity: working conventions

Read `docs/go-rewrite/DESIGN.md` first. (The research notes on the legacy apps it cites live outside the repository.)

## Layout

```
cmd/fpm/            console CLI, byte-compatible with legacy fpm.exe
internal/manifest/  components.xml -> model, validation, legacy policy rules
internal/state/     Components/<id> records, fpm.cfg, root discovery, components.bak
internal/plan/      request + state -> Plan (pure)
internal/fetch/     manifest + archive downloads (resume, verify, retry, mirrors)
internal/txn/       staging + journaled commit + recovery
internal/trust/     minisign signature verification + policy
internal/engine/    glue used by CLI and (later) GUI
testdata/manifests/ stable.xml, development.xml, small.xml (real snapshots)
testdata/records/csharp/  real Components/<id> files written by the C# manager
```

The exported types in each package's primary file (`manifest.go`, `state.go`, `plan.go`, `fetch.go`,
`txn.go`, `trust.go`) are the contract between packages. Extend them freely. Don't remove or rename
fields other packages may use without noting it in your report.

## Rules

- **Go 1.27, stdlib first.** Allowed extra modules: `golang.org/x/sys`, `golang.org/x/crypto`.
  Do not run `go mod tidy`, and don't add other modules. Ask if you need one.
- **Errors:** never panic on bad input, and never `log.Fatal` outside `cmd/`. Wrap with `%w`. Export
  sentinel or typed errors where callers need to branch (e.g. `errors.Is(err, fetch.ErrHashMismatch)`).
  Error messages are user-facing in the CLI: make them clear (what, which component, what to do).
- **Logging:** functions or structs that need it take a `*slog.Logger` (nil means discard). No global loggers.
- **Context:** anything that does I/O for more than a moment takes `context.Context` and honours cancellation promptly.
- **Paths:** FP-relative paths are slash-separated internally, and converted only at the record (de)serialization
  boundary. Treat Windows as case-insensitive when comparing FP-relative paths (`strings.EqualFold`, or a
  lowercased key). Validate every path that comes from the network (manifest `path`, zip entry names, IDs)
  before it touches the filesystem.
- **OS specifics** go in `_windows.go` / `_other.go` files. The code must build for
  `GOOS=windows GOARCH=amd64`, `GOOS=linux`, `GOOS=darwin`.
- **Tests:** table-driven, `t.TempDir()`, no real network (use `httptest`). Run `go vet ./internal/<pkg>/...`,
  `go test -race ./internal/<pkg>/...` and `GOOS=windows GOARCH=amd64 go build ./internal/<pkg>/...` before reporting.
- **Simple over clever.** No frameworks, no reflection magic, no premature interfaces. Comments explain *why*.
- **Server friendliness** (single origin, request budget): no extra HEAD requests, no polling, at most 2
  parallel downloads by default, exponential backoff with jitter, honour `Retry-After`.

## Priorities (learned during M1–M3)

- **Simple, not over-engineered.** Handle real errors properly (clear messages, no data loss, no hangs); no code for exotic or theoretical failures. A whole review pass was spent deleting defensive code; don't reintroduce it.
- **Reasonably secure, not paranoid:** path validation, transactional updates, verified downloads, signatures.
- **Be kind to the server:** at most 2 parallel downloads, backoff with jitter, resume instead of restart, no polling.
- **Visual testing is part of testing:** after GUI changes, render the screenshots and look at them.
- **Compatibility is non-negotiable:** the launcher contract and on-disk formats (DESIGN.md §1.1) stay byte-exact. `TestListGolden`, `TestCrashConsistency` and the record round trip against `testdata/records/csharp` guard them.
- **Platform:** Windows 10+, windows/amd64 only. macOS and Linux build for development (the GUI needs cgo there).

## Windows gotchas

- PowerShell `>` re-encodes output (UTF-16): use `cmd /c "... > file"` for byte comparisons.
- A handle with share mode 0 makes even `stat` fail; `archive/zip` returns DOS times as UTC.
- The launcher (Node/libuv) starts the manager in a kill-on-close job object and sets `ELECTRON_RUN_AS_NODE`; see DESIGN.md §4.6.
